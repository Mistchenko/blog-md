# Спецификация: блог из файлов Markdown

Учебный проект. Запускается только локально в режиме разработки, prod-деплоя и SEO нет.

## 1. Назначение

Сервис показывает статьи, которые хранятся на сервере как файлы Markdown.
Владелец создаёт `.md` файл в своём редакторе и сохраняет его в `volumes/data` —
статья появляется в UI без перезапуска и пересборки.
Посетитель видит слева дерево статей, справа — выбранную статью. Авторизации нет.

## 2. Стек

### Backend

- Python 3.14, FastAPI, uvicorn, pydantic-settings
- тесты — pytest + httpx2, покрытие — pytest-cov, типы — mypy (strict), линтер и форматирование — ruff, уязвимости — bandit

### Frontend

- Vite, Svelte 5 (runes), TypeScript
- SV5UI (Tailwind CSS 4, mode-watcher)
- markdown-it, DOMPurify, highlight.js
- тесты — Vitest + jsdom, покрытие — @vitest/coverage-v8, линтер — ESLint (с правилами безопасности), форматирование — Prettier

### Среда

- Docker, Docker Compose, Makefile-обёртка

## 3. Хранилище статей

- Корень хранилища — папка `volumes/data`, внутри контейнера `server` она смонтирована
  только для чтения в `/data` (env `DATA_DIR`).
- Выше корня прочитать файлы и папки нельзя.
- Имена используются как есть, с исходным регистром.

### 3.1. Правило имён

Каждый сегмент пути (папка или файл) должен:

- соответствовать `^[A-Za-z0-9._-]+$` — латиница, цифры, `-`, `_`, `.`;
- не начинаться с `.` (исключает `.`, `..`, `.DS_Store`, `.git`, `.swp` и т. п.);
- для файла статьи — оканчиваться на `.md` и иметь непустое имя до расширения.

Что не подходит под правило:

- скрытые (начинающиеся с `.`) — пропускаются молча;
- файлы с допустимым именем, но не `.md` — пропускаются молча;
- остальные (недопустимые символы) — пропускаются, в лог пишется warning
  (один раз на путь за время работы процесса);
- символические ссылки — не обрабатываются.

### 3.2. Защита путей (эндпоинт статьи)

1. Каждый сегмент пути из запроса проверяется правилом имён → иначе `400`.
2. Путь собирается от `DATA_DIR`, `resolve()` должен совпасть с несимлинкованным
   путём и лежать внутри `DATA_DIR` → иначе `404`.
3. Файл должен существовать и быть обычным файлом → иначе `404`.

## 4. Заголовок статьи

Имя статьи в дереве — **первая строка файла без символа `#`**:

- снимается BOM, затем все ведущие `#`, затем пробелы по краям;
- `# Большие языковые модели` → `Большие языковые модели`;
- если результат пустой — используется имя файла без `.md`.

## 5. Дерево

- В дерево попадают только `.md` файлы и папки, в которых на любой глубине есть статьи.
  Пустые папки не выводятся.
- Папки выводятся по имени как есть.
- Сортировка: сначала папки (по имени), затем статьи (по заголовку), без учёта регистра.

## 6. Backend API

Базовый префикс `/api`.

### `GET /api/health`

`{"status": "ok"}` — для healthcheck в compose.

### `GET /api/tree`

Корневой узел — папка с пустым `name`/`path`.

```json
{
  "type": "dir", "name": "", "path": "",
  "children": [
    { "type": "dir", "name": "AI", "path": "AI", "children": [
      { "type": "article", "name": "LLM.md", "path": "AI/LLM.md",
        "title": "Большие языковые модели", "updated_at": "2026-09-30T10:00:00Z" }
    ]},
    { "type": "article", "name": "about.md", "path": "about.md", "title": "…", "updated_at": "…" }
  ]
}
```

### `GET /api/articles/{path}`

`path` — путь относительно корня, с `.md`, например `/api/articles/AI/LLM.md`.

```json
{ "path": "AI/LLM.md", "title": "…", "content": "…сырой markdown…", "updated_at": "…" }
```

Ошибки: `400` — недопустимый путь, `404` — статьи нет. Тело: `{"detail": "..."}`.

### Кэширование

Нет. Каждый запрос читает файловую систему заново — новый файл виден сразу.

## 7. Frontend

### 7.1. Раскладка

- Слева — дерево статей (SV5UI `Tree`), справа — статья.
- На узких экранах дерево открывается в выдвижной панели (`Drawer`) по кнопке.
- Светлая/тёмная тема — по системной настройке (mode-watcher), с переключателем.

### 7.2. Маршруты (History API)

- `/` — главная: `about.md` из корня, если он есть, иначе заглушка «Выберите статью»
- `/article/<путь без .md>` — статья, `/article/AI/LLM` ↔ `AI/LLM.md`
- любой другой адрес — «Страница не найдена»

Префикс `/article/` нужен, чтобы адреса статей не пересекались со служебными путями
dev-сервера Vite (`/src/…`, `/@vite/…`). Работают «назад/вперёд» и прямой заход по ссылке.

### 7.3. Дерево

- Открытая статья подсвечена, путь до неё раскрыт, папки сворачиваются.
- Клик по статье — переход на её URL.

### 7.4. Статья

- Markdown рендерится на клиенте: markdown-it → DOMPurify, подсветка кода highlight.js,
  оформление — Tailwind Typography (`prose`).
- Относительные ссылки на `.md` (`../Python/async.md`, `async.md#раздел`) переписываются в
  маршруты SPA (`/article/Python/async#раздел`) и открываются без перезагрузки.
  Ссылки, выходящие за корень хранилища, остаются как есть.
- Внешние ссылки открываются в новой вкладке.
- Состояния: загрузка, `404` «Статья не найдена», ошибка сети.

### 7.5. Обновление данных

При возврате на вкладку (`visibilitychange`/`focus`) дерево и открытая статья
перезапрашиваются. SSE нет.

## 8. Среда исполнения

- Всё запускается только через Docker, в том числе для разработки.
- В рабочих директориях проекта не появляются `node_modules`, `venv`, `__pycache__`:
  - `server`: зависимости ставятся в системный Python образа (`uv pip install --system`),
    `PYTHONDONTWRITEBYTECODE=1`, pytest без cache provider;
  - `app`: `node_modules` лежит в образе в `/opt/node_modules`, код смонтирован в `/opt/app`
    (Node находит модули, поднимаясь по дереву каталогов), кэш Vite вынесен из `/opt/app`.
    Новая зависимость: `npm install --package-lock-only` в контейнере + пересборка образа.
- SV5UI рассчитан на SvelteKit: компоненты `Link`, `Header`, `Sidebar`, `NavigationMenu`
  импортируют `page` из `$app/state`. В приложении на чистом Vite этот модуль заменён
  `app/src/lib/sveltekit-state.ts` (alias в `vite.config.ts`), `sv5ui` исключён из
  пребандлинга, чтобы замена не попала в бандл с отдельной копией роутера.
- Hot-reload: uvicorn `--reload` для backend, Vite HMR для frontend.
- Порты на хосте: frontend `5173`, backend `8000`. Vite проксирует `/api` → `server:8000`.

## 9. Контроль качества

- Тесты (`make test`):
  - backend — pytest, `server/tests`;
  - frontend — Vitest в окружении jsdom, `app/tests`.
- Проверка типов (`make check`):
  - backend — mypy в строгом режиме по `src` и `tests`: у всех функций полные аннотации,
    без неявного `Any`; плагин `pydantic.mypy`; кэш в `/tmp` контейнера;
  - frontend — svelte-check (`"strict": true` в `tsconfig.json`); аналог строгого режима mypy —
    в линтере: `explicit-module-boundary-types` (явные типы у экспортируемых функций)
    и `recommendedTypeChecked` (запрет незаметного `any`, «забытых» промисов и т. п.).
- Линтеры — `make lint`, автоисправление — `make lint-fix`:
  - backend — ruff check, `[tool.ruff.lint]` в `server/pyproject.toml`: E, W, F, I, B, UP, SIM, C4, PT, RUF;
    отключены RUF001–RUF003 («похожие» символы — кириллица в строках и комментариях);
  - frontend — ESLint, `app/eslint.config.js`: рекомендуемые правила @eslint/js, typescript-eslint
    с проверкой типов (`recommendedTypeChecked`, типы из `tsconfig.json`),
    eslint-plugin-svelte, правила безопасности и `complexity: 10`; правила оформления отключены
    eslint-config-prettier; предупреждения тоже считаются провалом (`--max-warnings 0`).
- Поиск уязвимостей во frontend — в составе линтера:
  - eslint-plugin-no-unsanitized — запись непроверенного HTML в DOM;
  - eslint-plugin-security, кроме `detect-object-injection` (ложные срабатывания на любое `obj[key]`).
- Поиск уязвимостей в backend — bandit (`make bandit`) по `src` и `tests`, падает при любой находке;
  настройки в `[tool.bandit]` в `server/pyproject.toml`, в тестах отключено только B101 (`assert`).
- Форматирование — `make format` применяет, `make format-check` проверяет без изменений:
  - backend — ruff format, `[tool.ruff]` в `server/pyproject.toml`: строка до 100, кэш в `/tmp` контейнера;
  - frontend — Prettier + prettier-plugin-svelte, `app/.prettierrc.json`: строка до 100,
    без `;`, одинарные кавычки, запятая после последнего элемента.
- Покрытие кода тестами — строки и ветки, порог 90% (`make coverage`):
  - backend — pytest-cov по `server/src/blog`, порог `fail_under` в `server/pyproject.toml`;
  - frontend — Vitest + V8 по `app/src/lib`, пороги `thresholds` в `app/vitest.config.ts`;
    компоненты `.svelte` не входят в замер, их поведение проверяется в браузере;
  - данные и отчёты покрытия пишутся в `/tmp` контейнера, на хосте не появляются.
- Цикломатическая сложность (McCabe) — не больше 10 на функцию (`make complexity`):
  - backend — radon: `radon cc src -n C` (ранг C и хуже — сложность выше 10), непустой вывод — провал;
  - frontend — ESLint, правило `complexity: 10`, для `.ts` и `<script>` в `.svelte`;
    отдельный конфиг `app/eslint.complexity.config.js`, он же входит в конфиг линтера.
- Отчёт по сложности всех функций — `make complexity-report` (radon cc, ESLint).
- Перед коммитом — git-хук `.githooks/pre-commit` (подключается `make hooks`):
  `format-check`, `lint`, `check` только для затронутой части (`server/` и/или `app/`);
  тесты, покрытие и bandit в хук не входят, чтобы коммит оставался быстрым.

## 10. Вне рамок

Prod-сборка, SEO, RSS, поиск, картинки в статьях, frontmatter, черновики,
сортировка по префиксам, SSE, авторизация, редактирование через UI.
