# Python venv: справочное пособие

## Что такое venv и зачем он нужен

Виртуальное окружение (venv) — это изолированная среда, содержащая собственную копию интерпретатора Python и независимый набор установленных пакетов. Модуль `venv` входит в стандартную библиотеку Python начиная с версии 3.3 и является официально рекомендованным инструментом для создания виртуальных окружений.

Основная проблема, которую решает venv: разные проекты могут требовать несовместимые версии одной и той же библиотеки. Если приложение A нуждается в версии 1.0 модуля, а приложение B — в версии 2.0, установка любой из них в глобальное окружение сделает одно из приложений неработоспособным. Виртуальные окружения позволяют каждому проекту иметь собственный набор зависимостей, не затрагивая системную установку Python.

Ключевые характеристики venv:

- Создаётся поверх существующей установки Python (называемой «базовой»).
- По умолчанию изолирован от пакетов базового окружения.
- Содержит собственные исполняемые файлы `python` и `pip`.
- Является «одноразовым» — его можно удалить и пересоздать в любой момент.
- Не должен включаться в систему контроля версий (добавляйте в `.gitignore`).


## Проверка доступности venv

Модуль `venv` входит в стандартную поставку Python 3, но в некоторых дистрибутивах Linux (например, Debian, Ubuntu) он может быть вынесен в отдельный пакет. Для проверки выполните:

```bash
python3 -m venv --help
```

Если модуль доступен, отобразится справка по его параметрам. Если нет — установите пакет:

**Debian / Ubuntu:**

```bash
sudo apt install python3-venv
```

**RHEL / Fedora:**

```bash
sudo dnf install python3-virtualenv
```

Также убедитесь, что установлен `pip` — начиная с Python 3.4 он включается в поставку по умолчанию.


## Создание виртуального окружения

### Базовый синтаксис

```bash
python3 -m venv <путь_к_окружению>
```

Флаг `-m` указывает, что модуль `venv` запускается как исполняемый скрипт. Второй аргумент — путь к директории, в которой будет создано окружение. Если директория не существует, она будет создана автоматически, включая родительские каталоги.

### Типичные варианты создания

**Создание окружения с именем `.venv` в текущем каталоге проекта:**

```bash
python3 -m venv .venv
```

Имя `.venv` является соглашением: точка делает директорию скрытой в Unix-подобных системах, а также предотвращает конфликт с файлами `.env`, используемыми некоторыми инструментами для хранения переменных окружения.

**Создание окружения с произвольным именем:**

```bash
python3 -m venv myenv
```

**Создание окружения на основе конкретной версии Python (если в системе несколько интерпретаторов):**

```bash
python3.11 -m venv .venv
```

Модуль `venv` использует ту версию Python, из-под которой он был запущен.

**Создание окружения в другом каталоге:**

```bash
python3 -m venv ~/environments/project_env
```

### Структура созданной директории

После выполнения команды будет создана следующая структура:

| Элемент | Назначение |
|---|---|
| `bin/` (Linux/macOS) или `Scripts/` (Windows) | Исполняемые файлы: `python`, `pip`, а также скрипты активации |
| `lib/` (Linux/macOS) или `Lib/` (Windows) | Установленные библиотеки |
| `include/` | Файлы, необходимые для компиляции некоторых пакетов |
| `pyvenv.cfg` | Конфигурационный файл с настройками окружения |

В каталоге `bin` (или `Scripts`) размещаются скрипты `activate`, `activate.csh`, `activate.fish` и `deactivate` для различных оболочек.


## Активация виртуального окружения

Активация — это процесс, который изменяет переменные окружения текущей оболочки так, чтобы команды `python` и `pip` указывали на интерпретатор и пакетный менеджер виртуального окружения.

### Linux / macOS

```bash
source .venv/bin/activate
```

Для оболочки `fish`:

```bash
source .venv/bin/activate.fish
```

Для `csh`:

```bash
source .venv/bin/activate.csh
```

### Windows

**Командная строка (cmd.exe):**

```cmd
.venv\Scripts\activate.bat
```

**PowerShell:**

```powershell
.venv\Scripts\Activate.ps1
```

**Git Bash:**

```bash
source .venv/Scripts/activate
```

### Признак успешной активации

После активации в приглашении командной строки появится имя окружения в круглых скобках:

```
(venv) user@host:~/project$
```

Это визуальное подтверждение того, что вы работаете внутри виртуального окружения.

### Проверка активного окружения

Убедиться, что используется правильный интерпретатор:

```bash
which python    # Linux / macOS
where python    # Windows
```

В выводе должен присутствовать путь к директории `.venv`, например:

```
/path/to/project/.venv/bin/python
```


## Управление пакетами внутри окружения

После активации все команды `pip` автоматически устанавливают пакеты в виртуальное окружение, а не в глобальную систему.

### Установка пакетов

```bash
pip install package_name
```

Пакет будет установлен в директорию `site-packages` текущего виртуального окружения.

### Установка конкретной версии

```bash
pip install package_name==1.0.4
pip install "package_name>=1.0.4"
```

### Просмотр установленных пакетов

```bash
pip list
```

### Обновление pip внутри окружения

После создания окружения рекомендуется обновить `pip` до последней версии:

```bash
pip install --upgrade pip
```


## Файл requirements.txt

Файл `requirements.txt` — стандартный способ фиксации зависимостей проекта. Он позволяет воспроизвести окружение на другой машине.

### Создание файла

```bash
pip freeze > requirements.txt
```

Команда `pip freeze` выводит список всех установленных пакетов с точными версиями.

### Установка из файла

```bash
pip install -r requirements.txt
```

Эта команда установит все пакеты, перечисленные в файле, с указанными версиями.

### Пример содержимого requirements.txt

```
Django==4.2.0
requests>=2.28.0
numpy==1.24.3
```


## Деактивация виртуального окружения

Для выхода из виртуального окружения используется команда:

```bash
deactivate
```

После её выполнения приглашение командной строки вернётся к обычному виду, а команды `python` и `pip` снова будут указывать на системную установку.


## Удаление виртуального окружения

Виртуальное окружение — это обычная директория. Для его удаления достаточно рекурсивно удалить её:

**Linux / macOS:**

```bash
rm -rf .venv
```

**Windows (cmd):**

```cmd
rmdir /s /q .venv
```

**Windows (PowerShell):**

```powershell
Remove-Item -Recurse -Force .venv
```

После удаления можно создать новое окружение с чистого листа.


## Полезные опции создания venv

Модуль `venv` поддерживает ряд параметров, которые могут быть полезны в特定ных сценариях:

| Опция | Описание |
|---|---|
| `--system-site-packages` | Даёт доступ к пакетам базового окружения Python |
| `--clear` | Очищает целевую директорию перед созданием |
| `--upgrade` | Обновляет существующее окружение |
| `--without-pip` | Создаёт окружение без pip |
| `--prompt PROMPT` | Задаёт альтернативное имя в приглашении командной строки |
| `--copies` | Копирует файлы интерпретатора вместо создания символических ссылок |
| `--symlinks` | Использует символические ссылки (поведение по умолчанию в Linux/macOS) |

Полный список параметров доступен по команде:

```bash
python3 -m venv --help
```


## venv vs virtualenv

`virtualenv` — сторонний инструмент, предшественник `venv`. Начиная с Python 3.3, `venv` стал встроенной заменой, однако между ними есть различия:

| Критерий | venv | virtualenv |
|---|---|---|
| Включён в Python | Да, с версии 3.3 | Нет, устанавливается отдельно |
| Поддержка Python 2 | Нет | Да |
| Скорость создания | Медленнее | Быстрее (использует app-data seed) |
| Функциональность | Базовый набор | Расширенный набор опций |
| Официальная рекомендация | Да | Для особых случаев |

Официальная документация Python рекомендует использовать `venv` для всех новых проектов на Python 3.3+. `virtualenv` остаётся актуальным при необходимости поддержки Python 2 или при работе в специфических средах, где требуются расширенные возможности.


## Типичные сценарии использования

### Сценарий 1: Новый проект

```bash
mkdir myproject
cd myproject
python3 -m venv .venv
source .venv/bin/activate
pip install django requests
pip freeze > requirements.txt
```

### Сценарий 2: Клонирование существующего проекта

```bash
git clone https://github.com/user/repo.git
cd repo
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

### Сценарий 3: Работа с несколькими версиями Python

```bash
# Окружение для Python 3.11
python3.11 -m venv .venv311

# Окружение для Python 3.12
python3.12 -m venv .venv312
```


## Частые ошибки и их решения

**Ошибка: `No module named venv`**

Модуль не входит в базовую установку дистрибутива. Установите пакет `python3-venv` (Debian/Ubuntu) или `python3-virtualenv` (RHEL/Fedora).

**Ошибка: `command not found: python3`**

Python 3 не установлен или не добавлен в PATH. Установите Python 3 и убедитесь, что он доступен из командной строки.

**Пакеты устанавливаются в глобальное окружение, а не в venv**

Проверьте, активировано ли окружение. В приглашении командной строки должно быть имя окружения в скобках. Также проверьте путь к `python` командой `which python`.

**Ошибка при активации в PowerShell: `execution of scripts is disabled`**

Измените политику выполнения скриптов:

```powershell
Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser
```

**Приглашение не меняется после активации**

Убедитесь, что вы используете правильный скрипт активации для вашей оболочки. Для `fish` используйте `activate.fish`, для `csh` — `activate.csh`.

## Рекомендации

1. **Всегда создавайте виртуальное окружение** для каждого проекта, использующего сторонние пакеты.
2. **Именуйте окружение `.venv`** — это стандартное соглашение, которое делает директорию скрытой и предотвращает конфликты.
3. **Добавляйте `.venv/` в `.gitignore`** — виртуальное окружение не должно попадать в репозиторий.
4. **Фиксируйте зависимости** через `requirements.txt` и обновляйте файл при изменении состава пакетов.
5. **Обновляйте pip** после создания окружения: `pip install --upgrade pip`.
6. **Не размещайте код проекта внутри директории окружения** — окружение должно оставаться «одноразовым» и легко удаляемым.
7. **Используйте одну версию Python для создания и активации** — окружение привязано к той версии интерпретатора, из-под которой оно было создано.
